# 数据契约

计算引擎对输入文件的约定。任何一条不满足，引擎都不会报错，只会算错或按 0 计，所以跑 `calc` 之前先跑 `check`。

## 一、项目目录

```
<项目目录>/
├── Buildings_csv/          # DWG 导出的楼栋面积线，一个楼栋一个 CSV，文件名即楼号
│   ├── 1.csv
│   └── 2.csv
├── 楼栋属性.xlsx            # 楼栋清单 + 户型配比（决定户数）
├── 系数key.xlsx             # 面积换算系数（决定四类面积）
└── 补充信息.xlsx            # 项目级参数（用地面积、人防、车位等）
```

目录名 `Buildings_csv` 与 `buildings_csv` 都识别（见 `data_loader.DataLoader.BUILDINGS_DIR_NAMES`）。

## 二、面积线 CSV

两列：`图层`、`面积`。`图层` 是唯一的主键来源，格式两种：

| 段数 | 格式 | 例 | 楼层取值 |
| --- | --- | --- | --- |
| 4 段 | `AA/AB-楼型-楼层-系数key` | `AB-GC-BZC-设备平台` | 具体楼层，如 `1F`、`B1`、`ROOF`、`BZC(2:8)` |
| 3 段 | `AA/AB-楼型-系数key` | `AB-LP-设备平台` | 记为 `--` |

四个字段的用途：

- `AA/AB`：图层分类前缀，引擎不参与计算，仅保留分组。
- `楼型`：进 `楼型` 列，`query_area(btype=...)` 用它筛选（如上海按 `LP`/`YF`/`BZF` 拆分）。
- `楼层`：进 `楼层` 列，只认 4 段格式的行；3 段格式记为 `--`，**不参与 `floor=1f` 查询**。
- `系数key`：进 `系数key` 列，与 `系数key.xlsx` 关联出四类面积系数。

段数不是 3 或 4、或段内有空值，该行会被丢弃（`load_buildings` 按段数分流）。

## 三、系数key.xlsx

必需列：`系数key`、`计容`、`物理`、`销售`、`赠送`。

引擎据此计算四类面积：

```
计容面积 = 面积 × 计容系数
物理面积 = 面积 × 物理系数
销售面积 = 面积 × 销售系数
赠送面积 = 面积 × 赠送系数
```

奖励楼栋的计容面积会再 `÷ 奖励系数`（`update_factor` 设定）。

实际数据里还有一列 `超低能耗面积`，**程序没有任何地方读取它**，超低能耗奖励口径尚未实现。
新增系数列时同步改 `data_loader.build_analysis_data`，否则列存在但不生效。

## 四、楼栋属性.xlsx

固定列：`楼号`、`排序`、`单元数`、`每单元户数`、`层数`、`类型`、`是否精装`、`是否奖励楼栋`。

其余列**全部视为户型配比列**：引擎排除上面八列后，对剩余列整体求和，得到总户数
（`metrics_helpers.MetricsHelper._total_households`）。

- 列名自由，实际数据里按产品命名（如 `小高143`、`大高183`、`户型105`）。
- 列名以「保障」开头的行会计入保障房户数（`_safe_affordable_households`），
  商品房户数 = 总户数 − 保障房户数。
- `是否奖励楼栋` 原始值 `1/0` 会被转换成 `Y/N`。
- `类型` 含 `配套` 的楼栋会被识别为配套楼栋（`_refresh_building_views`）。

**引擎不校验 `楼号` 与 `Building_csv` 的覆盖范围。** 楼栋属性里有、面积线里没有的楼号，
其户配仍全额计入总户数，而面积类指标只覆盖有面积线的楼栋 —— 两张口径会并列在同一张指标表里。
`check` 会把这个情况列为警告。

## 五、补充信息.xlsx

必需列：`指标名称`、`数值`。引擎按 `指标名称` 读取项目级参数。

各城市规则实际读取的键如下，`缺失即报错` 指该键为分母，缺失会抛异常；其余缺失时按 0 参与计算：

| 城市 | 读取的键 |
| --- | --- |
| 上海 | **用地面积**（缺则报错）、不计容配套面积、电缆夹层面积、人防地下室面积、地下机动车数量、门卫 |
| 长沙 | **用地面积**（缺则报错）、商业面积、计容配套面积、不计容配套面积、骑楼面积、地库面积、人防地下室面积、地下机动车数量、地面停车、绿地面积、配套基底面积、商业基底面积 |
| 合肥 | **用地面积**（缺则报错）、商业面积、计容配套面积、不计容配套面积、地库面积、人防地下室面积、地下机动车数量、地面停车、绿地面积、配套基底面积、商业基底面积 |
| 贵阳 | **用地面积**（缺则报错）、地下停车场面积、人防地下室面积、地下机动车数量 |

文件里可以放更多键（配套用房面积、车位明细等），引擎会把它们原样并入输出表。

## 六、静默按 0 的三条路径

引擎用 `left join` + `fill_null(0)` 构建底表，以下情况不报错：

1. **系数key 未定义**：面积线里出现 `系数key.xlsx` 中没有的 key，该行计容/物理/销售/赠送全为 0。
   判断是否正常：若该 key 已被 `主体` 覆盖（如 `套内` 是主体的分项），按 0 计才正确；
   若是独立面积项却被漏配，指标会偏小。
2. **楼号未匹配**：`楼栋属性.xlsx` 里没有该楼号，`类型`、`是否精装`、`是否奖励楼栋` 为空，配套识别失效。
3. **补充信息缺键**：非分母键缺失时按 0 计，例如缺 `商业基底面积` 会让建筑密度偏小。

## 七、校验与诊断

`scripts/validate_project_data.py` 独立于引擎运行，覆盖：图层命名合法性、面积可解析性、
系数key 交叉命中、楼号交叉命中、完全没有 1F 的楼栋、楼栋属性与面积线覆盖错位、
各城市补充信息必需键、系数表里未被程序使用的列。

引擎内部还会生成一张 `数据诊断` 表（`data_loader.build_diagnostics`），随指标表导出为
同一工作簿的第二个 sheet。它与上面的校验器是两套实现：校验器可在跑计算前单独调用；
诊断表在 `load_data` 时自动生成，带**涉及面积与占面积线比例**，用于判断某个静默按 0 的项
到底影响多大。诊断只读，不改变任何计算结果（四城市快照回归不受影响）。
