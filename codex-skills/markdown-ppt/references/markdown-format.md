# Markdown 排版规范（工具内核实际解析的语法）

权威来源是工具的解析器与帮助文档：`backend/parser/markdown_parser.go`、`frontend/public/markdown-guide.md`。本文件是写稿时的工作副本，二者冲突时以代码为准。

配套样例：`frontend/public/sample_all_layouts.md`（覆盖全部版式，可直接导入或用作写作模板）。

## 一、页面类型（自动识别）

| 页面类型 | 触发方式 | 说明 |
| --- | --- | --- |
| 封面 `cover` | 文档开头第一个 `# 标题` | 可带副标题与 `汇报单位：` / `地点：` / `日期：` |
| 目录 `contents` | 封面之后自动生成 | 自动收集后续各页标题，不需要手写 |
| 过渡页 `transition` | 有 `## 标题` 但该页无正文 | 章节分隔 |
| 内容页 `content` | 其余情况 | 自动检测布局或按 `<!-- layout: -->` 指定 |
| 结束页 `end` | 标题为 `谢谢 / 感谢 / Thank You / Thanks / 致谢 / Q&A / 问答` | 缺失时自动追加一页 |

## 二、内容布局

### 1. 数据卡片 `datacards`

数值指标并列展示。每行 4 段（后段可省略），也可写 `标签：数值`（≥3 行自动触发）。

```markdown
<!-- layout: datacards -->
- 老旧小区改造|8|万亿元|占比 40%+
- 地下管网升级|6|万亿元|占比 25%
```

### 2. 三流程 `3flow`

恰好 3 个带序号的阶段；每行 `- **标题**|标签|描述|图标:名称,图标:名称`。

```markdown
<!-- layout: 3flow -->
- **上游：战略规划**|高毛利|把控全周期成败|策划:体检策划,规划:更新规划
- **中游：EPC**|低毛利|空间转化核心执行|设计:设计施工,改造:改造实施
- **下游：运营**|高毛利|持续经营收益|运营:产业运营,资产:资产管理
```

### 3. 五列卡片 `5col`

5~8 个并列要点，每行 `- 标题|描述`。

```markdown
<!-- layout: 5col -->
- 中央财政专项补助|东部最高 8 亿元
- 地方专项债|资本金最高占 20%
- 超长期特别国债|2026 年投放 2900 亿元
```

### 4. 左右对比 `compare`

用 `## 左:标题` 与 `## 右:标题`（中英文冒号均可）分栏，每栏下列 `- 项目|描述`。

```markdown
<!-- layout: compare -->
## 左:央企优势
- 投融资能力|资金雄厚、成本低
## 右:民企优势
- 机制灵活|决策快、反应敏捷
```

### 5. 双栏信息 `2info`

两个 `### 面板标题` 分组，每组写列表项。

```markdown
<!-- layout: 2info -->
### 市场规模
- 老旧小区改造 8 万亿元
### 竞争格局
- 央企主导 — 投融资强
```

### 6. 径向图 `radial`

`> 中心主题`（可多行）+ 每行 `- 外围项|描述`。

```markdown
<!-- layout: radial -->
> 政策与实施细则
> 全面落地
- 组织体系|成立领导小组
- 省级政策|出台实施方案
```

### 7. 时间线 `timeline`

每行 `- 日期|事件`；日期含年份/季度/月份，≥3 行自动触发。

```markdown
<!-- layout: timeline -->
- 2020.10|上升为国家战略
- 2025.05|中办国办印发意见
```

### 8. 图文混排 `mixed`

图片行与文本行交替（Z 字形），无需写 layout 指令，图片行+文本行并存即触发。

```markdown
![业务全景](https://placehold.co/600x400?text=Business =600x400)
这里是业务全景的介绍文字。
```

### 9. 表格 `table`

标准 Markdown 表格（表头行 + `| --- |` 分隔行 + 数据行），列数需一致。

```markdown
| 项目 | 负责人 | 进度 |
| --- | --- | --- |
| 模块A | 张三 | 80% |
```

### 10. 文本段落 `text`

连续自然段，段落间空行分隔。推荐显式声明，否则连续行可能被判成列表。

```markdown
<!-- layout: text -->
第一段连续文本。

第二段连续文本。
```

## 四、自动布局检测顺序

1. `mixed`：图片行 + 文本行并存
2. `table`：出现 Markdown 表格分隔行
3. `datacards`：`标签：数值` 行 ≥ 3
4. `timeline`：含日期关键词的行 ≥ 3
5. `2info`：含 `###` 分组且列表项 ≥ 4
6. `3flow`：恰好 3 个带序号项目
7. `5col`：5~8 个列表项
8. `text`：只有连续文本、无列表项

> 需要精确控制版式时，在页面内容开头写 `<!-- layout: 布局名 -->`，优先级高于自动识别。

## 五、常见问题

- 连续文本变成了列表 → 加 `<!-- layout: text -->`。
- 表格错位 → 表头与分隔行、数据行列数必须一致。
- 页面数量与预期不符 → 记住自动补的目录页与结束页；先用 `markdown-ppt parse -i deck.md --pretty` 检查。
- 区块被拆成两页 → `---` 必须是独立一行（前后可有空白，不能与其他文字同行）。
