# 商用 image → DWG/DXF 技术架构对比

> 说明：本文基于公开产品形态、通用 CV/ML 工程实践和本 skill 的实测归纳，
> 不是对任何厂商内部实现的披露。不同产品、不同输入类型的差异很大。

## 结论

商用 image → DWG/DXF 通常不是一个“图片进、DXF 出”的端到端模型，而是多阶段流水线：

```text
图片/PDF
  → 图像归一化
  → 矢量基元（线、弧、轮廓）
  → 语义层（墙、门、窗、文字、尺寸）
  → 约束求解与拓扑修复
  → CAD 实体 + 图层 + 单位
  → 人工复核 / 再训练
```

真正拉开差距的通常是：

1. 大量“原图 + CAD 真值”数据；
2. 墙、门、窗、文字的领域先验；
3. 几何合并、吸附、拟合和拓扑修复；
4. 置信度与人工修正流程；
5. 对 PDF 矢量输入的特殊处理。

单个模型或矢量化库只是其中一环。

## 典型分层

| 阶段 | 常见做法 | 主要目标 |
| --- | --- | --- |
| 输入与预处理 | 纠偏、透视校正、去噪、二值化、分色、去背景网格、超分辨率、切图 | 让后续几何提取更稳定 |
| 几何提取 | 骨架化、轮廓追踪、Hough/LSD 直线检测、Douglas-Peucker 简化、RANSAC 拟合直线/圆/圆弧 | 得到线、弧、闭合轮廓 |
| 语义识别 | 语义分割找墙/房间/家具，目标检测找门窗/符号，OCR 找房间名和尺寸 | 从“线”变成“构件” |
| 几何重建 | 墙线配对成中心线+厚度，洞口从封边线/墙带缺口推断，门窗符号识别，墙节点求交 | 得到可编辑的 CAD 几何 |
| 约束修复 | 正交/45°吸附、共线合并、端点吸合、墙厚统一、门窗宽度范围、尺寸链标定 | 让结果像 CAD，而不是描图 |
| CAD 导出 | 写 `LINE/LWPOLYLINE/ARC/CIRCLE/HATCH/TEXT/INSERT`，分图层、颜色、线型、单位 | 变成可继续编辑的 DWG/DXF |
| 质量闭环 | 置信度、待复核标记、人工修图界面、错误回流训练 | 把“能看”提升到“能用” |

## 输入类型决定难度

| 输入 | 典型技术 | 难度 | 说明 |
| --- | --- | --- | --- |
| CAD 导出的 PDF | 解析 PDF 内容流，提取路径、文字和坐标，再映射到 DXF | 低 | 本来就是矢量，精度可以很高；很多“效果惊艳”的案例属于这一类 |
| PNG/JPG 线稿 | 二值化 + 矢量化 + 直线/圆弧拟合 + 语义重建 | 中 | 几何较干净，但仍有断线、碎线、文字轮廓 |
| 扫描件 | 上述流程 + 纠偏、去噪、去阴影、OCR | 高 | 噪声、倾斜、线宽变化会直接影响墙厚和洞口 |
| 照片/效果图 | 透视校正、颜色分离、分割模型、遮挡处理 | 很高 | 阴影、纹理、家具遮挡会让墙体识别不稳定 |

所以评估商用服务时，先确认它处理的是 **PDF 矢量** 还是 **真正的栅格图片**，
两者不是同一难度级别。

## 商用效果好的原因

### 1. 领域先验很重

平面图不是任意图形：

- 墙通常正交；
- 墙厚在有限范围；
- 门宽常见 700–1000mm；
- 窗有固定画法；
- 房间名有固定字高；
- 尺寸链可以提供比例标定。

把这些规则写进后处理，通常比单纯换更大的模型更能提升“像 CAD”的程度。

### 2. 训练数据是核心资产

高质量系统通常有大量成对数据，并用 CAD 批量渲染生成合成样本：

- 改墙厚、开间、门窗位置；
- 换字体、线宽、填充；
- 加扫描噪声、模糊、旋转、透视；
- 自动得到像素级标注。

这类数据规模和标注一致性，是普通开源工具很难直接复制的。

### 3. 输出经过大量清理

商用结果通常不会“把每个墨迹描一遍”，而会：

- 合并碎线；
- 拉直墙线；
- 统一墙厚；
- 补节点和转角；
- 识别门窗；
- 把文字变成可编辑 `TEXT`；
- 把重复门窗变成图块。

看起来干净，很大一部分来自规则和人工修正。

### 4. 有人工复核环节

不少商用服务后台有审核/修图流程，或提供交互式修正界面。
宣传图通常是修过的最终结果，不是模型一次输出的原始结果。

### 5. DWG 导出是成熟工程

DXF 可以直接用 `ezdxf` 等库写；DWG 通常通过 ODA SDK、RealDWG 或格式转换器完成。
这部分不是识别难点，难点在几何和语义。

## 端到端模型的边界

学术上有 image-to-CAD、sketch-to-CAD、CAD 序列生成等方向，但平面图转 DXF
对尺寸精度、单位、图层和可编辑性要求很高。纯端到端模型容易出现：

- 线看起来对，但端点不闭合；
- 圆变成折线；
- 文字变成轮廓；
- 墙厚不统一；
- 门窗语义丢失；
- 无法保证毫米单位。

因此商用系统更常见的是“CV/ML 提候选 + 规则重建 + 人工确认”，
而不是一个大模型直接输出最终 DXF。

## 与本 skill 的差距

现有链路已经具备：

- 骨架/轮廓混合描线；
- Hough 墙配对；
- 门窗洞口推断；
- OCR 文本层；
- 图层和 DXF 输出；
- 背景网格去除、共线/端点吸附、前后叠加对比。

与商用系统的主要差距通常是：

1. 缺少墙/门/窗的语义分割模型；
2. 缺少大规模真实图纸评测集；
3. 圆弧拟合和符号识别还不够；
4. 缺少尺寸链自动标定；
5. 缺少置信度与人工修正界面；
6. 对扫描件、照片、复杂填充图的鲁棒性有限。

如果继续往商用方向走，建议优先级：

1. 建几十到几百张真实图纸的评测集，固定墙/洞口/文字/尺寸指标；
2. 用合成数据训练墙体和门窗分割；
3. 把分割结果交给现有几何重建和约束修复；
4. 给每个推断结果打置信度，低置信度进入人工复核；
5. 最后再考虑端到端模型。

## 评估商用服务的检查清单

不要只看宣传图，重点检查导出的 DXF/DWG：

- 单位是否正确（`$INSUNITS` 或图纸单位）；
- 墙是闭合多段线、矩形，还是大量单线；
- 圆和圆弧是否保留为 `ARC/CIRCLE`，还是被折线化；
- 文字是否是可编辑 `TEXT/MTEXT`，还是笔画轮廓；
- 门窗是否分图层、是否有块或语义对象；
- 是否存在大量重复线、断头、未闭合节点；
- 图层、颜色、线型是否符合后续制图习惯；
- 是否包含原图底图或只包含矢量；
- 结果是否需要人工清理，清理成本是多少。

一句话：**商用 image-to-DXF 的核心是“几何流水线 + 领域语义 + 数据闭环”，
不是单一模型；PDF 矢量输入和人工修图，往往比宣传里看起来的 AI 占比更大。**
