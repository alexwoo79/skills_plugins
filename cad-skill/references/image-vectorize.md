# 图片 → 矢量：线稿、实心厚墙平面图与实心图形

定位：**描图助手**。它把栅格图变成"候选几何"，语义（这条是墙、那是门）仍然靠人确认。
不要把扫描的照片、手绘草图直接送进来期待成套平面图。

> 怎么用、参数怎么调、输出什么图层、出错怎么办：见 `references/image-to-dxf.md`。
> 本文只讲算法与实测数据。

两条路线，先分清图是什么：

| 图是什么 | 用哪个脚本 | 出什么 |
| --- | --- | --- |
| 双线线稿（CAD 导出） | `image_to_calls.py` | 默认单线 DXF（A-SKETCH/A-TEXT）；`--mode walls` 才出 plan.json/洞口 |
| 实心厚墙平面图（家装/售楼图） | `image_to_walls.py` | DXF（墙体矩形 + 线work 分层）、`plan.json`（仅墙） |
| 实心图形（logo、图标、笔画文字） | `image_to_vector.py` | SVG（even-odd 填充）或多边形 + 填充的 DXF |

三者算法完全不同：双线线稿走直线检测配平行线对，实心厚墙走**厚度分离 + 骨架化取中心线**，
实心图形走**轮廓描摹**。拿错脚本只会得到一堆碎线或错误的墙。

```text
线稿图片 → 标定（可选）→ 矢量化
                        ├→ 默认 hybrid：单线 DXF（A-SKETCH / A-TEXT）
                        └→ --mode walls：plan.json → calls.json / .scr / 结构化 DXF
              ↘ 预览 PNG（结构化模式必须人工确认）
```

## 混合描线（默认 lines 模式）

`image_to_calls.py` 的默认出口是 `--tracer hybrid`，目标不是“抽墙”，而是**保真复刻线稿**：

1. 长边归一化到 `--max-side`（默认 2048），自适应 Otsu；
2. **细描边线**细化成 1px 骨架，按端点/交点切图走线，再用 Douglas-Peucker
   简化成多段线（`A-SKETCH`）；一条笔画只输出一条 PLINE，圆弧/曲线保留为折线；
3. **填充区域**（局部厚度 ≥ `--solid-px`，如实心墙、柱、色块）走外轮廓 + 孔
   （`A-SOLID`）并加 SOLID 填充（`A-HATCH`），不压成中线；
   `--all-skeleton` 可强制整张图都走单线；
4. 可选 `--ocr-text`：识别文字写成 `TEXT`（`A-TEXT`），并默认移除原文字笔画；
   `--keep-text-strokes` 可保留。macOS 用 Vision，默认 `zh-Hans,en-US`（中文优先），
   其他平台回退 Tesseract；Windows 需安装 Tesseract + pytesseract + `chi_sim` 语言包，
   缺依赖时 `--ocr-text` 会带 `ocr_hint` 返回安装命令（见 `references/setup-windows.md#ocr`）。

输出统计带分阶段计时：`ocr_ms` / `trace_ms` / `ms`，以及 `sketch` / `solid` / `texts`。
没有标定时坐标是工作图像素（`$INSUNITS=0`）；给了 `--px-per-mm` 才是毫米。

实测（同一张 `demo-input.png`，1080×810）：

| 模式 | 实体 | 文本 | 耗时 |
| --- | --- | --- | --- |
| 参考服务（NASJI） | 401 多段线 | 7（英文） | 3608 ms |
| 本项目 hybrid（默认） | 1024 细线 + 12 填充区域 | 0 | 361 ms |
| 本项目 hybrid + OCR | 719 线 + 12 填充 + 11 文本 | 11（含 BATH） | 667 ms |

## 输入与预期

| 输入 | 效果 |
| --- | --- |
| CAD 导出的 PDF/PNG 线稿（建议 ≥150 dpi） | 好：墙线与洞口基本全中，见下面实测 |
| 扫描件（有噪声、轻微倾斜） | 可用但需修补：开 `--deskew --adaptive --despeckle`，召回下降一档 |
| 照片（透视、阴影、手绘） | 不要用：先纠正投影去阴影，或者干脆当底图人工描 |

## 标定（推荐；不标定则输出像素）

图像没有单位。不标定也能出 DXF，但坐标是像素（`$INSUNITS=0`），不要当成毫米。
两种方式：

```bash
# 方式一：直接给比例
--px-per-mm 0.2

# 方式二：在图上量两个点的像素坐标 + 真实距离（毫米）
--calibrate "120,80 1440,80" --real 12000

# 原点：哪个像素对应 CAD 的 (0,0)，默认取图像左下角
--origin 40,1640
```

原点搞错的后果是**整体平移一个常量**（实测少给原点会整体偏 200mm），所以预览里要
连带核对一个已知尺寸。

## 常用命令

```bash
# 一、结构化：出 plan.json（推荐），可直接接 wall_plan.py / cad_direct.py
```

```bash

```

## 预处理：背景网格与几何吸附

默认仍走“保真”路径，不清理任何墨迹。只有确认图上有方格纸/瓷砖底纹，或成品 DXF 里
碎线、断头明显时，才加 `--clean-geometry`：

```bash
python3 scripts/image_to_calls.py scan.png --clean-geometry \
    --px-per-mm 0.2 --out-dxf clean.dxf
```

### 背景网格去除（`--remove-grid`）

算法只处理“贯穿画布 + 细 + 近似等距”的线：

1. 对二值墨迹做行/列投影，找贯穿率 ≥ `--grid-min-coverage`（默认 0.55）的细线；
2. 对候选位置按间距聚类，至少 `--grid-min-lines` 条（默认 4）成等差数列才判为网格；
3. 只清这些线附近的窄带；用距离变换和垂直/水平支撑保护粗笔画与穿网而过的墙线。

这样不会因为“线很长”就删掉两根普通墙线。但真实轴网本身也可能等距，所以默认关闭；
误删时先调高 `--grid-min-lines`，或改用 `--snap-geometry` 只做几何清理。

### 共线/端点吸附（`--snap-geometry`）

hybrid 后端在骨架上做，hough/`walls` 后端在线段上做，步骤相同：

1. **共线合并**：端点相邻、方向近似相反、且都贴近对方延长线的两段接成一条；
2. **轴向吸附**：整条近似水平/垂直的折线统一吸到一个坐标，消除 0.1–1px 台阶；
3. **端点吸附**：近邻端点吸到同一点；近似直角时吸到两线交点；
4. **T 形接头**：端点投影到附近长线段上，补上骨架/霍夫断开造成的小缺口；
5. **共线点压缩**：删掉落在相邻两点连线上的中间点，减少 DXF 顶点数。

所有动作都受像素容差限制（`--snap-tol` 默认 2.5px），不会把相距很远的线硬连。

| 输入 | 墙召回 | 洞口召回 | 轴位置误差 | 厚度误差 | 洞口宽度误差 | 洞口位置误差 |

## 关键参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--min-wall` / `--max-wall` | 80 / 500 mm | 认成墙的平行线间距范围，墙厚不在此区间就配不上 |
| `--min-opening` / `--max-opening` | 500 / 4000 mm | 洞口宽度范围 |
| `--door-min` / `--door-max` | 700 / 1000 mm | 仅按宽度猜门/窗的区间（**只是猜测**） |
| `--merge-tol` | 30 mm | 同一直线的合并容差 |
| `--join-gap` | 150 mm | 允许接上的小间断，要远小于最小洞口宽，否则会把洞口接掉 |
| `--grid` / `--grid-shift` | 10 / 15 mm | 网格吸附间距与允许位移 |
| `--angle-tol` | 3° | 轴线判定容差，超出归为斜线（不参与配墙） |
| `--stairs` | 关 | 识别直跑楼梯（等距平行踏步线）并写进 `plan.json`；默认不识别 |

## 识别逻辑要点（为什么这样做）

- **墙 = 平行线对**：配对优先取重叠最长的组合、再取间距更大的，这样窗中线（只跨洞口）不会
  抢掉真正的两条墙面线。
- **洞口 = 用封边线定位**，而不是墙身缺口：窗的三线画法会把墙身缺口填平，只看缺口会漏掉所有窗。
  两条封边线之间还必须确有"洞口出处"——要么左边正好是某段墙身的终点、右边是另一段的起点（门），
  要么有一条窗线正好从左边跨到右边（窗）。
- **填充墙的洞口 = 墙带占空比下降**：家装/营销图的墙是"灰填充 + 黑描边"，门窗处常常保留
  一圈封边线或门槛线，单看线对会漏。额外沿每条墙中心线量墙带墨量，取该墙自身的 75 分位作基线，
  连续低于基线 65% 且宽度在洞口范围内的段记为洞口（`openings_from_band`）。
  纯线稿图基线低于 0.5 时整条规则自动跳过，不影响原来的双线路径。
- **门/窗类型**：先按宽度猜（700–1000 记为门），再用"门扇线"证据修正（洞口边缘有垂直于墙、
  伸进房间且长度约等于门宽的线）。
- **门的合页侧与开向**：对每扇门枚举 start/end × positive/negative 四条 90° 候选弧，
  在二值图上逐点采样投票；墙中心线可能被线宽/家具带偏，评分时再试 ±4/8/12px 和半个墙厚的横向偏移。
  真实画出的弧覆盖率通常接近 1，其余候选接近 0；
  最高分不够高或与第二名差距太小就保留默认并标 `needs_review`。
  弧证据足够强时，还会把宽度误判成窗的洞口改回门（`door_swings_reclassified`）。
  比 `--door-max` 宽 25% 以上的洞口不会用门扇线硬判成平开门，避免把大窗/推拉门认错。
- **楼梯**：`--stairs` 时先找"等长、等距、互相平行、重叠足够"的短线簇（≥5 条），
  换算成 `stairs` 规格并从墙配对里摘掉——否则 260mm 的踏步间距会被配对成一面假墙。
  只支持正交直跑梯段。

## 已知局限（务必告诉用户）

1. **窗仍是猜测；门有弧证据**：600mm 宽可能是卫生间窗，也可能被记成窄门，看图确认。
   有开启弧的门能确认合页侧和开向；找不到弧的门会在 `review` 里列为待确认。
2. **只认正交墙**：`--angle-tol` 之外的斜墙不参与配墙，会落到 `unpaired_lines` 里。
3. **不读标注文字**：尺寸数字、房间名不做 OCR，需要人工补（尺寸可用现有 `add_dimension`）。
4. **扫描件必然要修**：8/10 的洞口召回意味着平均每面墙要人工补一两个洞口。
5. **预览必须看**：识别结果先落 plan.json / calls.json，确认后再落图——与 skill 一贯的
   "先确认方案、再分步落图"一致。
6. **楼梯只认直跑**：弧形梯、旋转梯、带休息平台断开的梯段识别不到；踏步等距假设太强的图
   也可能漏检。

## 一句话工作流

线稿 → 标定 → 矢量化（门开向/可选楼梯）→ **看预览确认** → `plan_render.py` 出同一套
calls/scr/DXF/SVG → 落图 → 把 `review` 里列出的猜测项手工补实。

## 实心图形 / logo：`image_to_vector.py`

```bash
python3 scripts/image_to_vector.py logo.png \
    --out-svg logo.svg --out-dxf logo.dxf \
    --px-per-mm 0.25 --epsilon 0.8 --min-area 20 --pretty
```

做法：Otsu 自动分层（取占比较小的那侧为前景，所以白字黑底也能自动认，不用手工 `--invert`）
→ 轮廓提取（外轮廓 + 内孔两级层级）→ 多边形简化 → 输出。指标会直接打在 stdout 上：
轮廓数、孔数、顶点数、**面积比**与 **IoU**（把多边形重新栅格化后与原图比，这就是"描得像不像"的量化）。

细节与取舍：

| 项 | 说明 |
| --- | --- |
| 超采样 `--supersample`（默认 4） | 放大**连续通道**后再卡阈值，得到亚像素边界。直接放大二值掩膜会整体外扩（实测 IoU 0.98→0.95）；关闭超采样则轮廓会整体偏小（面积比 0.984） |
| Otsu 阈值的坑 | 硬边图上 Otsu 会把阈值落在某一类的灰度值上（实测暗部 20、阈值也是 20），直接用作切分点会让插值出的中间灰度全落到背景侧，因此改取两类均值的中间值 |
| `--epsilon` | 简化容差（像素）。0.2→616 顶点、0.8→377、3.0→193；IoU 在 0.95–0.98 之间变化很小，说明瓶颈是原图分辨率而不是简化 |
| 孔怎么表示 | SVG 用 `fill-rule="evenodd"` 的多子路径；DXF 里外轮廓与孔各成闭合多段线，填充用带**岛检测**的 HATCH（每形状一条），在 CAD 里是实心的 |
| 尺寸 | `--px-per-mm` 决定图纸单位；输出以外接框左下角为原点，SVG 同时写出 mm 宽高 |

实测（DeepSeek logo 位图 461×465，`--epsilon 0.8 --supersample 4`）：9 个外轮廓（鲸鱼 + 8 个字母）、
9 个内孔、367 个顶点、**IoU 0.982、面积比 0.997**、SVG 5.8 KB、DXF 18 条多段线 + 9 个带岛填充。

局限：

1. **单色**：目前按"前景/背景"两分，多色图只能取前景的轮廓（颜色取前景均值），不做分色描摹。
2. **分辨率决定下限**：小尺寸位图（如 461px 的 logo）文字笔画会有轻微走形，IoU 上限约 0.98；
   给更高分辨率的原图能直接改善。
3. **文字变轮廓**：输出的是笔画轮廓，不是可编辑字体；要改字得重新出图。
4. 斜线/细笔画在 `--epsilon` 过大时会明显走形，默认 0.8 是"保真优先"的取值。

测试：`tests/test_image_to_vector.py`（合成圆环/带孔方框/噪点，验证轮廓与孔、保真度、
超采样修正、SVG 子路径数、DXF 填充岛路径）。

## 实心厚墙平面图：`image_to_walls.py`

家装/售楼平面图里墙是**填充色块**（本样本：墙深灰 ≈113、家具线浅灰 ≈212），没有"两条平行线"
可配，必须按厚度分墙：

```bash
python3 scripts/image_to_walls.py plan.png --out-dxf plan.dxf \
    --out-plan walls.json --min-wall-px 8 --pretty
```

流水线：深色掩膜 → 按 `--min-wall-px` 开运算滤掉更细的线（家具 3px、房间名笔画 6px）
→ Zhang-Suen 骨架化取中心线（纯 numpy，不需要 opencv-contrib）→ 按行/列切成正交墙段、
用距离变换量厚度 → 出图。图层：

| 图层 | 内容 |
| --- | --- |
| `A-WALL` | 墙体，默认闭合矩形（`--walls centerlines` / `both` 可选中心线，另进 `A-WALL-CL`） |
| `A-TRACE` | 其余线work：家具、洁具、门窗开启线、文字笔画（`--no-trace` 可关） |
| `A-ROOM` | 房间轮廓，**只有显式 `--rooms` 才生成**（见下） |

**默认不生成房间闭合线、也不输出面积**：默认只算"建筑外壳"（封门窗后填洞的轮廓）
用来剔除室外线work，不做分水岭分割。需要房间几何或面积统计时加 `--rooms`，
需要中心标注再加 `--room-labels`。

### 彩色图：三道"别把填色当墙"的过滤

彩色效果图里地板、木饰、彩色家具都是有饱和度的中间调，只看灰度会把它们整片当墨迹。现在按顺序过三道：

| 过滤 | 参数 | 作用与实测 |
| --- | --- | --- |
| 饱和度 | `--sat-max`（默认 90） | 墙体近黑且中性，地板/木饰是有饱和度的 → 直接排除。合成对照：加与不加，墙体结果完全一致（测试 `test_coloured_floor_is_not_wall`） |
| 厚度 | `--min-wall-px`（默认 8→10） | 家具线 3px、房间名笔画 6px 被开运算去掉 |
| 块状物 | `--blob-size-ratio`（默认 5） | 两个方向都大于 5 倍墙厚、且外接框填得很满的连通域按家具色块剔除。本样本上精准命中 2 个（`73×218px`，填充率 0.90–0.91 的沙发/床块，合计 29k 像素） |

### 空间（房间）识别（`--rooms`，默认关闭）

房间分割用的是"外壳 + 分水岭"，不依赖洞口识别。**默认不跑**——只有要房间几何
或面积统计时才加 `--rooms`（默认输出里既没有 `A-ROOM` 闭合线，也没有面积字段）：

1. **外壳**：闭运算按 `--seal-mm`（默认 3000）封住门窗 → 填洞 → 取最大连通域 → **裁到墙网外接框**
   （不裁的话闭运算把外壳撑到图边，边距会被当成室内：实测合成图上多出 4 个假房间、面积接近真实值的两倍）。
2. **种子**：室内自由空间里"离墙 > `--door-half-mm`"（默认 450）的区域作种子——门口是窄颈，房间中心离墙远。
3. **分水岭**：在室内自由空间内生长到边界，颈部自然成为分界，于是门口两侧分开成两个房间。
4. **真实性校验**：房间边界必须由真墙支撑（`--room-wall-support`，默认 0.5），闭运算造出的假区域会被筛掉。

实测（彩色效果图 2400×1808、0.1335 px/mm）：识别出 **8 个房间、合计 77.7m²**
（毛面积按尺寸链 10.36×10.12 = 104.8m²，扣掉墙体后量级合理），明细
`[24.7, 15.8, 12.6, 11.8, 4.8, 3.3, 2.5, 2.2] m²`。

**未标定时**毫米阈值没有意义（450mm 会当成 450px），此时按实测墙厚推导：
封洞尺度 12×墙厚、门口半宽 3×墙厚、最小房间面积 (12×墙厚)² 像素²，并在返回值里
把面积只报成像素。另一张灰图（窗口更大、画法不同）在同一套参数下只分出 2 个房间——
需要调 `--door-half-mm` / `--room-wall-support`，这一点如实记在这里，不当成通用效果承诺。

### 保持画面整洁

- 默认 `--trace-inside-only`：只保留**室内**线work，尺寸链、指北针、图签这些室外内容不进 DXF
  （本样本滤掉 467 条）。
- 家具/洁具不再被当成墙（上面三道过滤），房间用干净的多边形放 `A-ROOM`，可以直接填充或标注。
- 房间文字默认不写，需要时 `--room-labels`。

### 清掉房间里的纹理碎线

地板/瓷砖纹理、房间名与尺寸文字的笔画，在矢量结果里就是**大量短线 + 密排线**。
清理阶段用两条规则（都在室内线work 上做）：

| 规则 | 参数（默认） | 命中对象 |
| --- | --- | --- |
| 太短 | `--trace-min-mm 250` | 文字笔画、填充记号 |
| 又短又密 | `--trace-dense-len-mm 800` + `--trace-dense-radius-mm 150` + `--trace-dense-count 12` | 地板/瓷砖/织物纹理的密排短线 |

实测（彩色效果图 2400×1808）：线work **5295 → 1488 条**（删短 1636 + 删密排 2591），
而长度 ≥1500mm 的长边（家具轮廓、台面、柜体）在任意规则组合下 **842/842 全保留**。
DXF 从 880KB 降到 286KB。

注意两点：

1. 门开启弧这类**曲线**会被 H/V 分段切成短段，默认会被当碎线删掉；要保留就把
   `--trace-min-mm` 调到 120 左右。
2. 想完全不清理用 `--no-trace-clean`；未标定时阈值同样按实测墙厚推导
   （最短 2×墙厚、密排判定 8×墙厚/半径 4×墙厚），返回值里 `trace_clean_basis`
   会说明这次用的是毫米还是墙厚。

实测（1012×1252 家装平面图，0.8 秒）：

| 指标 | 值 |
| --- | --- |
| 墙段 | 63（H 36 / V 27） |
| 墙厚分档 | 18.8px（46 段，外墙/承重）、10.2px（17 段，隔墙） |
| 墙体覆盖率 / IoU | 0.987 / 0.891 |
| 线work | 686 条（A-TRACE） |

端部延伸策略也实测过（同一张图）：两端延伸 覆盖率 0.9871 / 精度 0.9010，不延伸 0.9199 / 0.9062，
只延伸接头端 0.9325 / 0.9058——采用**两端延伸半墙厚**，因为多画出来的主要是转角方块，
本来就在墙身约定之内（`wall_plan` 同样延伸）。`--no-extend-ends` 可关。

### 定标：优先读图上的尺寸链

效果图/售楼图常常带尺寸链，这是最可靠的比例来源。步骤：

1. **求和**：把一条链上的数字加起来（顶链 3280+1850+1950+3280 = 10360mm）。
2. **量像素**：量这条链两端对应的**相邻墙中心线**像素间距，逐段都算一遍再取平均：
   `px_per_mm = 像素间距 / 毫米`。
3. **逐段复核**：把量到的每段换算成毫米，与链上数字比；误差应在百分之几以内。
4. **自检厚度**：换算出的墙厚是不是落在 100/120/200/240 附近？差得离谱说明比例错了。

> 不要用"整体外接框"定标：阳台、飘窗的凸出会被算进去。我在本样本上先按外框估成
> 0.1516 px/mm，偏了 12%，改用尺寸链逐段拟合后是 **0.1335 px/mm**（顶部链逐段误差 <0.6%）。

同一张图提取完的复核（提取结果里真实存在的中心线节点）：

| 顶部链 | 3280 | 1850 | 1950 | 3280 |
| --- | --- | --- | --- | --- |
| 提取出的间距 | 3281 | 1843 | 1955 | 3273 |
| 误差 | +1 | −7 | +5 | −7 |

合计偏差 20mm / 10360mm = **0.19%**——也就是说墙线位置与图纸自己标的尺寸对得上。

**注意：这类效果图的墙厚不按比例。** 同一张图换算出来是 151mm（隔墙）与 267mm（承重），
不是整数模数。要不要用 `--snap-thickness "120,240"` 吸附由你决定：吸附后 DXF 更规范、
但像素覆盖率会从 0.968 掉到 0.786（墙被改薄了）。默认不吸附，并把 `thickness_raw`
与 `thickness_classes`（含"未吸附"一档）都报出来。

已知局限：

1. **没有单位**：不给 `--px-per-mm` 或 `--calibrate "x1,y1 x2,y2" --real 毫米`，几何就是像素，
   `plan.json` 的墙厚（≈19/10）会被 `wall_plan.py` 判为异常——脚本会在 `scale_note` 里提示。
2. **不做洞口**：门窗洞口、房间名、尺寸都不识别；门窗开启线会进 `A-TRACE`，洞口要人工补。
3. **只认正交墙**：斜墙/弧墙在骨架里会变成短段或毛刺，被 `--min-segment-px` 过滤掉，需人工补。
4. 墙厚取距离变换的中位数，转角与交汇处会略微偏厚。

测试：`tests/test_image_to_walls.py`（合成 18px 厚墙 + 3px 家具线 + 6px 房间名，
验证分墙与厚度、细线不当墙、纯细线图报错、DXF 图层与数量、标定单位、延伸对覆盖率的提升）。
